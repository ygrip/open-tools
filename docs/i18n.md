# Internationalization (Paraglide JS)

The platform recognizes twelve locales, with permanent prefixed static routes except for English:

| Code | Language | URL prefix |
| --- | --- | --- |
| en | English | none |
| id | Bahasa Indonesia | /id |
| ms | Bahasa Melayu | /ms |
| fil | Filipino | /fil |
| th | Thai | /th |
| vi | Vietnamese | /vi |
| zh | Simplified Chinese | /zh |
| my | Burmese | /my |
| km | Khmer | /km |
| lo | Lao | /lo |
| ja | Japanese | /ja |
| hi | Hindi | /hi |

- English and Indonesian remain the **fully maintained** host and legal translations, and the only locales currently indexed by search engines. Their social cards and hreflang entries are preserved.
- All host navigation, runtime/permission and shared-UI-kit strings use the same **Paraglide JS** catalogs in `messages/{locale}.json`. New languages still require native-speaker review; some legal content and tool-owned copy may be incomplete. Do not claim all tool interfaces are translated.
- The picker uses one searchable accessible modal on desktop and mobile, with local names, English aliases, matching country flags, arrow-key navigation and Escape to close.
- Changing languages uses client-side SvelteKit navigation without replacing the current iframe or losing tool input, focus or output. The parent relays locale changes through `trick-it:localechange`. Route, query and fragment are retained. Asset URLs and verified bundle requests stay unprefixed.
- The source of truth for language labels/codes is `src/lib/languages.js`. Register each new locale in `project.inlang/settings.json` and add its `messages/<locale>.json` file. Place host/runtime/shared-kit copy directly in that file as `runtime__...` and `ui__...` keys, not in per-locale TypeScript files.
- `npm run i18n:compile` runs Paraglide and `scripts/generate-host-locales.mjs`, which produces ignored `src/lib/i18n/generated-copies.ts`. This small build-time adapter is necessary because the isolated `srcdoc` sandbox cannot import host modules. Never edit generated output. The adapter projects the **same Paraglide JSON source** into nested runtime/SDK dictionaries; no second translation source exists.
- Each standalone tool still owns and versions its translations. Tools may use Paraglide during their own build, but the host cannot import their code or accurately translate tool-specific text by scanning DOM nodes. Avoid mutation-observer phrase replacement and declare `manifest.locales` only for genuinely translated interfaces.
- SEO paths are generated with `localePath()`. Only `SEO_LOCALES` (currently en/id) are indexed or receive individually rendered cards. New locale pages use the English card and `noindex,nofollow` to avoid duplicate fallback content in search engines. Index a language only when full content and social assets are reviewed.
- Localized tool metadata is selected only when the tool declares the translation. Tool bundles are versioned independent products: their own `locales` metadata controls the language actually sent into their opaque-origin sandbox. The host falls back to the first tool-supported language when the selected platform language is unavailable, showing a fallback notice. There is no `allow-same-origin` exception.

## Verification

```sh
npm ci
npm run check
npm run test
npm run build
npm run test:e2e
```

Verify direct navigation to language-prefixed home, legal and tool pages; keyword filtering in the modal; narrow mobile viewports; correct `html lang`, preserved query/hash, appropriate tool iframe fallback, and no accidental indexed English fallback.
