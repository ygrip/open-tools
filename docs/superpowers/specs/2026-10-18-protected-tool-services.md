# Protected tool services

Keep local tools inside the existing opaque sandbox. Allow reviewed tools to declare optional Worker-backed features without direct network access. The initial service is PageSpeed SEO; this request explicitly authorizes the Worker exception to the earlier client-only requirement.

`services` is an optional v3 manifest array. Each entry contains a unique lowercase ID (maximum 32 characters), an allowlisted handler (`pagespeed-seo` initially), `rateLimit: { limit, periodSeconds }` (1–60 requests, 10 or 60 seconds), and `turnstile: boolean`. No service URLs, keys, arbitrary binding names, or script execution are accepted. Nonempty services require a declared `services` runtime permission. Legacy tools normalize to no services.

The SDK call is `trickIt.request('services', { feature: 'audit', input: { url, strategy, locale } })`. Existing session grants and one-action confirmations remain. The host shows the exact public URL, the configured request allowance, Google disclosure and, when required, a host-managed Turnstile challenge. UI text supports EN/ID. Tokens never enter the tool iframe. Challenge script is loaded only for protected requests. Close/denial, expiration, failure and navigation discard the token; each subsequent request receives a new widget/token.

Registry sync generates a server policy map from the validated pinned manifests and a Wrangler deployment configuration with one native rate-limit binding per feature. Tool ID, feature ID, bundle digest and version are checked by the Worker. Browser bodies cannot override protections. Handlers are selected from a host-owned allowlist. The only external audit target is Google's fixed API; the Worker never fetches arbitrary submitted URLs itself.

Server flow: validate same-origin JSON and bounded body; look up the deployed policy and release; validate the handler input; apply a shared attempt throttle; verify Turnstile success/action/explicit production hostname allowlist; enforce the feature's per-IP native rate limit; invoke the selected handler. Missing policy/bindings/secrets, token failure, replay, hostname/action mismatch and provider failure fail closed before auditing. Responses are no-store. Native counters are per Cloudflare location and IP, not an exact global quota. Local computation cannot be securely rate-limited; these protections apply to Worker-backed features.

The public sitekey is a Worker variable. The secret stays in the existing Worker's secret store. Widget: trick-it protected services; domains: tools.readynaz.com, localhost and 127.0.0.1. Production validation accepts only tools.readynaz.com. No real key/secret enters source or test fixtures. Google key remains optional; reliable production audits may require a dedicated Google project quota.

Verify contract rejection/compatibility, deterministic generated policies/bindings, protected requests including invalid/replayed/mismatched tokens, independent feature counters, browser consent/widget lifecycle, EN/ID, no loss of input, theme/mobile behavior, full unit/build/performance/browser suite and Worker dry run. Live provider success is separate from mocked checks. Do not claim deployed/live validation until it is exercised.
