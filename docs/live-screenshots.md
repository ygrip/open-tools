The PNGs are **full-page**; viewport dimensions specify the device emulation, not the final image height. [capture.json](screenshots/live/capture.json) records the actual dimensions and bytes for each image, capture timestamp, source URL, HTTP status, language, document theme, horizontal overflow, and page errors.

## Capture / refresh

Requirements: Node.js 22+, Playwright Chromium, network access to the public production domain.

```sh
npm ci
npx playwright install chromium
node scripts/capture-live-screenshots.mjs
```

The script always visits the production URL, checks HTTP 200 and the hero heading, sets the theme through the app's `open-tools-theme` storage key (rather than altering the DOM after render), and scrolls through the page to trigger lazy image loading. It captures the **actual homepage** with reduced motion to avoid mid-animation frames. It does not use a local dev server or modify the page's application content.

### GitHub-hosted capture

The [Live screenshot capture workflow](../.github/workflows/live-screenshots.yml) runs on a manually requested refresh and on the dedicated capture branch. It uses a GitHub-hosted Ubuntu browser because some local environments block outbound access. After **all four** screenshots pass validation, the workflow commits the generated assets and metadata to the same branch.

For future refreshes: create a dedicated branch, run the capture workflow against that branch (or use the command above in a machine with production access), review all four PNGs and [capture.json](screenshots/live/capture.json), and open a PR. A browser failure must fail the job: **do not substitute placeholders or the previous snapshot and call them live**.

This is a design documentation snapshot, **not** a substitute for responsive/accessibility testing or coverage of tool detail pages. Rendering errors and horizontal overflow recorded by the capture should be reviewed as separate issues.
